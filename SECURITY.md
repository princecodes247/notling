# Security Policy

## Supported Versions

We release patches and security updates for the current major version.

| Version | Supported          |
| ------- | ------------------ |
| 1.x.x   | :white_check_mark: |
| < 1.0.0 | :x:                |

---

## Reporting a Vulnerability

The Notling team and contributors take the security of our application and users' data very seriously.

If you believe you have found a security vulnerability in Notling, please **DO NOT** disclose it publicly via GitHub issues or discussions.

Instead, please report security issues privately:

- **Email**: [princegbalam247@gmail.com](mailto:princegbalam247@gmail.com)
- **Subject**: `[SECURITY VULNERABILITY] Notling - <Brief Summary>`

### What to Include in Your Report

To help us triage and resolve the issue quickly, please provide:
1. Description of the vulnerability and its potential impact.
2. Step-by-step reproduction instructions or a minimal Proof of Concept (PoC).
3. Any relevant logs, network requests, or screenshots.
4. Suggested remediation or patch if you have one.

### Response Timeline

- **Initial Response**: Within 48 hours acknowledging receipt of your report.
- **Triage & Assessment**: Within 5 business days with an assessment and estimated patch timeline.
- **Resolution & Release**: We will work on a fix in a private branch, verify it, and publish an advisory alongside a patched release.

We deeply appreciate your help in making Notling secure for everyone through responsible disclosure.
